Quarto vs. R Markdown

Quarto is the successor of R Markdown: same idea (text + code + output in one file), but one tool for R, Python and Julia, many output formats, and a cleaner syntax for chunk options (#| lines instead of {r, echo=FALSE}). Existing .Rmd files mostly render unchanged.

This module works with a small example project: c03/report/, rendered to HTML and PDF. Open report.qmd next to this page.

A project’s file structure

report/
├── _quarto.yml       shared settings for every .qmd in the folder
├── report.qmd        the report: YAML header, text, code chunks
├── references.bib    bibliography (BibTeX)
├── data/             input data
└── images/           static images

_quarto.yml holds everything that’s the same for all documents, so each .qmd header stays short:

execute:
  freeze: auto
  echo: false
  warning: false
  message: false

format:
  html:
    toc: true
    number-sections: true
    embed-resources: true
  typst:
    toc: true
    number-sections: true
    papersize: a4

bibliography: references.bib

The document’s own YAML header adds what’s specific to it:

---
title: "Karlsruhe Is Getting Warmer"
subtitle: "A short climate report from 150 years of daily weather data"
author: "Your Name"
date: today
---

Output formats

  • HTML: interactive (plotly works), one self-contained file with embed-resources: true.
  • PDF via Typst: modern, fast, no LaTeX installation needed. Our default for PDFs.
  • PDF via LaTeX (format: pdf): the classic route, needs a TeX distribution (quarto install tinytex), slower, but required by some journals’ templates.
  • Also: Word (docx), slides (revealjs), websites, books.

Render from the terminal, or with the Preview button in Positron:

quarto render report.qmd               # all formats in _quarto.yml
quarto render report.qmd --to typst    # just one
quarto preview report.qmd              # re-renders on every save

From R, the quarto package does the same:

quarto_render("c03/report/report.qmd")

Inline vs. preview

In Positron, chunks run inline in the console while you write (Ctrl/Cmd + Enter), using your current session. Rendering always starts a fresh R session from top to bottom, which is the check that your document is reproducible: a chunk that only works because of something you ran by hand will fail there.

Code chunks

Chunk options go in #| lines at the top of the chunk:

```{r}
#| label: fig-anomaly
#| fig-cap: "Annual mean temperature, deviation from the 1961-1990 mean."
#| echo: false
yearly |>
  ggplot(aes(x = year, y = anomaly)) +
  geom_col()
```

The most useful ones:

Option Effect
echo: false hide the code, show the output
eval: false show the code, don’t run it
include: false run it, show nothing (setup chunks)
warning: false / message: false hide warnings / messages
fig-cap, fig-width, fig-height figure caption and size (inches)
cache: true store the result, skip re-running (see below)

Inline code

Numbers in the text come straight from R, so they update when the data changes:

The warmest year on record is `r warmest_year`.

Compute such values in a chunk first and keep inline code short (one variable, maybe a round()).

Figures, tables, images

A chunk label starting with fig- plus a fig-cap makes a numbered figure you can refer to with @fig-anomaly. Tables work the same with tbl- and tbl-cap; knitr::kable() turns a tibble into a table:

```{r}
#| label: tbl-days
#| tbl-cap: "Average number of days per year."
period_means |>
  knitr::kable(digits = 1)
```

An alternative to kable() is tt() from the tinytable package. Its tables are styled out of the box and adapt on their own to HTML and Typst, and it’s what modelsummary uses for regression tables. format_tt() formats the numbers (num_fmt = "decimal" counts decimal places, the default counts significant digits):

```{r}
#| label: tbl-days
#| tbl-cap: "Average number of days per year."
p_load(tinytable)

period_means |>
  tt() |>
  format_tt(digits = 1, num_fmt = "decimal")
```

Static images use Markdown syntax, with an optional label for cross-references:

![Warming stripes for Karlsruhe.](images/stripes.png){#fig-stripes width=80%}

Text: formatting, links, formulas

**bold**, *italic*, `code`, [a link](https://quarto.org)

## A section heading

- a bullet point
1. a numbered item

Inline math: $\Delta T_t$. A display formula:

$$
\Delta T_t = \bar{T}_t - \frac{1}{30} \sum_{s \in R} \bar{T}_s
$$

Formulas are LaTeX by default: the HTML shows them with MathJax, and Quarto translates them for Typst. If you’d rather write Typst’s own math syntax (fewer backslashes and braces), my Quarto extension typst-equations renders Typst math in HTML and PDF alike. Useful links:

  • Typst: https://typst.app
  • Typst’s math syntax: https://typst.app/docs/reference/math/
  • converting LaTeX formulas to Typst: https://qwinsi.github.io/tex2typst-webapp/

Positron’s Visual editor mode (top right of a .qmd) shows the formatted result while you type, useful for long text.

References

Cite entries of the .bib file with @key, in brackets for parenthetical citations:

Data: Deutscher Wetterdienst [@dwd2026], analysed with the tidyverse [@wickham2023].

Quarto adds the bibliography at the end, or wherever a ::: {#refs} block stands. BibTeX entries come from Google Scholar, Zotero (with the Better BibTeX plugin), or the DOI (Positron’s visual editor: Insert → Citation).

Reproducibility at a glance

A reproducible analysis gives the same results on another computer, or on yours in two years. Tools that help, from small to big, mentioned here only:

  • Seeds: set.seed() makes random draws repeat (see “Random numbers and seeds” below).
  • targets is a pipeline tool: it works out the dependencies between all steps of a project itself, and only re-runs the steps whose inputs changed. Caching (next section) does the same for single chunks of one document.
  • renv records the exact package versions of a project in a lockfile, so others (or you, in two years) can restore them.
  • Docker freezes the whole system (OS, R, packages) into an image.

Caching: only re-run what changed

A report rerenders every chunk every time. That’s what makes it reproducible, and what makes it slow once a step takes minutes (a download, a big file, a model). Three tools, from coarse to fine:

freeze: skip whole documents

In _quarto.yml, freeze: auto re-runs a document’s code only when its .qmd changed. Results are stored in _freeze/. Useful in projects with many documents.

cache: true: skip single chunks

A cached chunk stores its results in report_cache/, and is re-run only when its code changes. The chunk below takes three seconds the first time, and none at all after that:

Sys.sleep(3) # stand-in for a slow step
weather <- read_csv("data/weather_karlsruhe.csv")

Declaring dependencies

The pitfall: the cache only watches the chunk’s code. If the data file changes, the old result is reused without notice. cache.extra adds anything else the result depends on, e.g. the file’s modification time:

```{r}
#| label: load-data
#| cache: true
#| cache.extra: !expr file.mtime("data/weather_karlsruhe.csv")
yearly <- read_csv("data/weather_karlsruhe.csv") |>
  ...
```

dependson: "load-data" does the same for a chunk that uses the results of another cached chunk.

Random numbers and seeds

Simulations, bootstrapping and random samples all draw random numbers, and every run draws different ones. rnorm() draws from a normal distribution, runif() from a uniform one; run this chunk twice and the numbers change:

rnorm(3)
[1]  0.1896666  0.0443924 -0.7566665
runif(3)
[1] 0.3659005 0.7067026 0.2986343

A report would then show different numbers after every render. set.seed() fixes the starting point of the random number generator: the same seed gives the same draws.

set.seed(2026)
runif(3)
[1] 0.6986735 0.5565305 0.1401400
set.seed(2026)
runif(3)
[1] 0.6986735 0.5565305 0.1401400

In a report, call set.seed() once, at the top of the setup chunk. Every render then draws the same numbers, as long as the random steps run in the same order.

With replace = TRUE, a row can be drawn more than once. As many rows as the data has, drawn with replacement, make a bootstrap sample, the basis of resampling methods:

weather |>
  slice_sample(prop = 1, replace = TRUE) |>
  summarize(temp_mean = mean(temp_mean, na.rm = TRUE))
# A tibble: 1 × 1
  temp_mean
      <dbl>
1      10.4
